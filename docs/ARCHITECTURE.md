# Architecture and ownership

`packet_parser.py` converts Scapy packets into immutable metadata Frames. It checks Dot11 presence and preserves missing RSSI as missing; it does not decode application payloads. For data frames it interprets ToDS/FromDS before choosing a BSSID; WDS has no inferred BSSID. A management deauthentication is type 0/subtype 12. An unparseable packet is skipped. The dataset adapter produces the same Frame representation from documented packet CSV fields.

`window_aggregator.py` is the sole rolling implementation for both training preparation and inference. Each transmitter/BSSID has a deque. Expired frames are removed, empty groups deleted, and long recording gaps skipped in constant time after buffers empty. Default global bounds are 100,000 buffered frames and 4,096 groups; exceeding them fails the session visibly rather than silently truncating statistical features. Timestamp regressions are rejected. A snapshot is computed before admitting a packet at a scheduled tick, so an exactly-on-tick frame is admitted to the following snapshot. Frames at or below end minus window are excluded. EOF emits a final partial observation; rates always use the configured full window duration, including warmup and EOF. Idle live traffic produces no new snapshots until another packet arrives; the displayed rate is explicitly the latest observation, not an instantaneous live rate.

`feature_extractor.py` defines 18 extracted measurements and a 16-feature predictive allowlist. RSSI mean/variability remain analysis-only due to verified antenna namespace differences between publisher CSVs and Scapy; inference applies the same exclusion as training. Matched real packet/CSV windows agree on all 16 inputs. Labels, identifiers, time and grouping keys remain analysis metadata. `preprocessing.py` creates the train-only median imputer (plus missing indicators) and balanced Random Forest. `inference.py` checks feature names, schema version, predictive allowlist, observation window and step before any prediction.

`detection.py` runs the rule and optional model without database coupling. `alerts.py` creates structured incidents and deduplicates by transmitter/BSSID/category using event time and a bounded cooldown map. Rule/ML disagreement is stored, not overridden. `storage.py` writes an observation and optional incident in one SQLite transaction. Each operation owns a short-lived connection; WAL and busy timeout reduce contention. Capture failure creates an error session. Status changes produce audit events. Session retention uses ingestion/end time, so replaying an old capture does not immediately remove it.

`monitoring.py` owns the worker, stop/pause events, event-time pipeline and bounded recent metadata. The Streamlit process caches exactly one Monitor/Storage pair per database path. Controls reject duplicate starts. The browser refresh fragment renews a 30-second worker lease; closing all tabs lets the worker stop, and interpreter exit also stops it. Threads are daemon threads. Live sniffing uses one-second capture timeouts, no stored Scapy packet list, and cannot pause. CLI fast replay has no browser lease. Restart always creates a new session ID and retains prior evidence. A process restart marks abandoned sessions interrupted.

The supported deployment is one local Streamlit process per database. Multiple processes sharing the same database are not coordinated and are not supported. Bind to localhost; this dashboard has no multi-user authentication. Long training and preparation are synchronous explicit UI actions; monitoring is disabled during these operations. A future large-scale system should move training and capture to dedicated supervised processes.

`dashboard/views.py` reads persistent results and controls the cached worker; it does not implement detection. `reporting.py` exports actual rows and creates static fitted-model charts. Countermeasure Protocol is an extension contract only: no blacklist or countermeasure claims are made.
